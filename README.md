# ValutaTrade Hub

**ValutaTrade Hub** — учебное CLI-приложение для управления валютным портфелем. Пользователь может зарегистрироваться, войти в аккаунт, просматривать портфель, покупать и продавать поддерживаемые валюты, а также получать актуальные обменные курсы.

Для получения курсов используется отдельный модуль **Parser Service**: он обращается к CoinGecko за курсами криптовалют и к ExchangeRate-API за курсами фиатных валют. Полученные данные приводятся к единому формату и сохраняются локально. Core Service использует локальный кеш `data/rates.json`, а не обращается к внешним API при каждой операции.

## Демонстрация

Запись демонстрации работы приложения: [ValutaTrade Hub — asciinema](https://asciinema.org/a/VWMcSduoCEFMiECX).

## Возможности

- регистрация и авторизация пользователей;
- просмотр портфеля и пересчёт его стоимости в выбранную базовую валюту;
- покупка и продажа валют с проверкой суммы и доступного баланса;
- просмотр списка поддерживаемых валют;
- получение курса между двумя валютами;
- получение курсов из CoinGecko и ExchangeRate-API;
- ручное обновление всех курсов или данных только одного источника;
- локальный кеш текущих курсов и отдельная история измерений;
- логирование доменных операций и ошибок.

Поддерживаемые валюты: USD, EUR, GBP, RUB, BTC, ETH и SOL.

## Требования

- Python 3.12 или новее;
- [uv](https://docs.astral.sh/uv/) для управления окружением и зависимостями;
- API-ключ ExchangeRate-API для получения фиатных курсов;
- доступ к сети для запросов к CoinGecko и ExchangeRate-API.

## Установка

Клонируйте репозиторий и перейдите в каталог проекта:

```bash
git clone <URL-репозитория>
cd finalproject_Timofeev_M26-555
```

Установите зависимости и синхронизируйте виртуальное окружение:

```bash
uv sync
```

В проекте используются `requests` для HTTP-запросов и `prettytable` для отображения таблиц в CLI. `ruff` используется для проверки и форматирования кода.

## Настройка API-ключа

Для получения фиатных курсов используется [ExchangeRate-API](https://www.exchangerate-api.com/). Ключ **не хранится в исходном коде или в `config.json`**: `ParserConfig` получает его из переменной окружения `EXCHANGERATE_API_KEY`.

В Linux/macOS задайте переменную в том же терминале, из которого будете запускать приложение:

```bash
read -rsp "ExchangeRate-API key: " EXCHANGERATE_API_KEY
echo
export EXCHANGERATE_API_KEY
```

Ввод ключа не отображается на экране. Проверить, что приложение видит переменную, можно командой:

```bash
uv run python -c "from valutatrade_hub.parser_service.config import ParserConfig; print('API key configured:', bool(ParserConfig().EXCHANGERATE_API_KEY))"
```

Ожидаемый результат при заданном ключе:

```text
API key configured: True
```

Переменная, заданная таким способом, действует в текущей сессии терминала. После открытия нового терминала её нужно задать снова. Не добавляйте настоящий ключ в Git, README или журнал команд.

Для CoinGecko в текущей учебной конфигурации используется публичный API без отдельного ключа.

Запустите приложение через зарегистрированную CLI-команду:

```bash
uv run valutatrade
```

Если окружение проекта активировано, можно запускать напрямую:

```bash

```

После запуска появится приглашение `valutatrade>`.

## Команды CLI

### Пользователи и портфель

| Команда | Назначение |
|---|---|
| `register --username NAME --password PASSWORD` | Зарегистрировать пользователя. |
| `login --username NAME --password PASSWORD` | Войти в аккаунт. |
| `logout` | Выйти из аккаунта. |
| `show-portfolio` | Показать портфель в базовой валюте по умолчанию. |
| `show-portfolio --base-currency EUR` | Показать стоимость портфеля в EUR. |
| `list-currencies` | Показать поддерживаемые валюты. |
| `help` | Показать справку. |
| `exit` | Завершить работу приложения. |

Новый пользователь регистрируется с пустым портфелем. Для успешной покупки на его USD-кошельке должен быть доступный баланс.

### Покупка и продажа

```text
buy --currency BTC --amount 0.001
sell --currency BTC --amount 0.001
```

`buy` покупает указанное количество валюты за USD. `sell` продаёт указанное количество валюты и зачисляет оценочную выручку в USD. Приложение проверяет корректность суммы, наличие курса и достаточность средств.

### Получение курса

```text
get-rate --from USD --to BTC
get-rate --from BTC --to USD
```

Перед запросом приложение проверяет коды валют и актуальность локального кеша. Если курс устарел или отсутствует, возвращается ошибка `ApiRequestError`; неизвестный код валюты вызывает `CurrencyNotFoundError`.

### Parser Service: обновление курсов

Обновить данные из обоих источников:

```text
update-rates
```

Обновить только криптовалютные курсы:

```text
update-rates --source coingecko
```

Обновить только фиатные курсы:

```text
update-rates --source exchangerate
```

Если один источник недоступен, Parser Service записывает ошибку в журнал и продолжает обновление по оставшимся доступным источникам. Если не удалось получить данные ни от одного источника, команда сообщает об ошибке обновления.

### Parser Service: просмотр кеша

```text
show-rates
show-rates --currency BTC
show-rates --top 2
show-rates --base EUR
```

- `--currency BTC` — показать курс указанной валюты;
- `--top 2` — показать две наиболее дорогие криптовалюты из настроенного списка;
- `--base EUR` — пересчитать отображаемые курсы относительно EUR.

## Кеш курсов и TTL

Параметры Core Service задаются в корневом `config.json`. В частности:

```json
{
    "rates_file": "data/rates.json",
    "rates_ttl_seconds": 300,
    "default_base_currency": "USD"
}
```

`rates_ttl_seconds` задаёт срок актуальности кеша в секундах. В приведённой конфигурации TTL равен 300 секундам (5 минутам). После истечения TTL `get-rate` не использует устаревшие данные как актуальные и сообщает, что кеш нужно обновить. Обновление запускается вручную командой `update-rates`.

### `data/rates.json` — текущий снимок

Core Service читает этот файл. В нём находятся:

- `rates` — текущие курсы в формате `КОД_ВАЛЮТЫ: USD-за-одну-единицу`; например, `BTC` содержит стоимость одного BTC в USD;
- `updated_at` и `last_refresh` — время обновления;
- `pairs` — сведения по валютным парам, включая курс, время обновления и источник;
- `sources` — источник для каждой пары;
- `source` — источники, участвовавшие в последнем обновлении.

Курсы CoinGecko приходят в USD за единицу криптовалюты. ExchangeRate-API запрашивается с базовой валютой USD; полученные фиатные значения инвертируются, чтобы сохранить единый формат — USD за одну единицу валюты.

### `data/exchange_rates.json` — история измерений

Файл содержит список исторических записей. Каждая запись хранит валютную пару, значение курса, время получения, источник и поле `meta`. Идентификатор формируется из валютной пары и UTC-времени измерения, например `BTC_USD_2026-11-09T17:30:01.969979Z`. Новые измерения добавляются в историю, а не заменяют предыдущие записи.

Запись JSON-файлов выполняется через `DatabaseManager` с использованием временного файла и атомарной замены целевого файла.

## Логирование

Операции приложения журналируются через `@log_action`. Записи включают время, тип действия, пользователя, параметры операции и результат. При исключениях фиксируются тип и сообщение ошибки; исключения затем передаются обработчику CLI.

Основной журнал: `logs/actions.log`. Путь, уровень и формат логирования задаются в `config.json`. Используется ротация файла журнала.

## Ограничения текущей реализации

- Обновление Parser Service запускается вручную командами `update-rates`; автоматический планировщик периодического обновления в текущем CLI-сценарии не используется.
- Новый пользователь получает пустой портфель; отдельная CLI-команда пополнения баланса не реализована.
- Источник курсов и время обновления сохраняются для каждой валютной пары. При частичном обновлении остальные ранее сохранённые курсы остаются в кеше.
